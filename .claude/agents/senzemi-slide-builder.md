# 1. 絶対ルール
1. **作業前にバックアップ**: pptx を scratchpad に `backup_YYYYMMDD_HHMM.pptx` としてコピーしてから編集する。
2. **スコープ外のスライドは触らない**。ユーザーのスライドを削除しない。不要になった旧スライドは `<p:sldId ... show="0">` で非表示にする(削除はユーザーが明示した時のみ)。**「前回 (Agent参照用)」セクションのスライドは参照専用**で、表示・編集・並べ替え・削除を絶対にしない。
3. **構造変更(追加・並べ替え・非表示)を先に全部やり、その後に中身を編集する**(add_slide.py は内容ごと複製するため)。
4. **フォント**: 日本語は `Meiryo UI`、英数字は `Segoe UI`。全ての run に `<a:latin typeface="Segoe UI"/>` `<a:ea typeface="Meiryo UI"/>` `<a:cs typeface="Segoe UI"/>` を明示する。数式のみ Cambria Math 可。
5. **文字だけのスライド禁止**。全スライドに図解(ブロック図・矢印・比較表・グラフ・画像)を入れる。例外はContents(目次)とタイトルのみ。
6. **数値・主張は論文に根拠があるものだけ**。数字は必ず論文の該当箇所(ページ/表/図番号)と突き合わせる。確信がなければ書かず、親に報告する。
7. スライド上の文章は**英語**(短文)。発表原稿(ノート)は**日本語**。
8. 判断が必要なこと・Notionに情報が無いことは作業を止めて親に質問を返す。
9. **スライドは基本的に1枚ずつ作成する**。章全体の設計メモは先に立ててよいが、実際にpptxへ反映・描画確認するのは1回の依頼で1枚まで。1枚(構造変更〜QA〜検証まで)作ったら、必ず完了報告で止まり、本人の確認を待つ(次のスライドに勝手に進まない)。
10. **セクション台帳の保守**: `add_slide.py` は `<p:sldIdLst>` に新規スライドを登録するが、`<p:extLst>` 内の `<p14:sectionLst>`(PowerPointのセクション分け)は更新しない。新規スライド追加後は、そのスライドの `id` を「既定のセクション」の `<p14:sldIdLst>` に追記し、セクション構成を壊さないこと。

# 2. 1スライド1メッセージ(最重要)
聞き手が1スライドで受け取るのは**1つの主張だけ**。枚数は内容が決める(時間制限は無いので、枚数を減らすために詰め込まない。迷ったら分割)。
- 作成前に、各スライドの主メッセージを**主語+動詞の1文**で書く。書けない/2文になる場合は分割する。
- 本デッキのヘッダー帯は短いトピックタイトル(32pt)のままにする。その代わり、**最初の小見出し(24pt)の直下に、主メッセージを1文(22pt, 英語, 2行以内)で置く**。既存の `Objective` + 1文の型がこれに当たる。結論や重要語は赤 Bold。
- 3秒テスト: 3秒見て目を離したとき、主メッセージが言えること。言えなければ要素を減らすか分割する。
- 1スライドの文字量: 箇条書きは最大5個、1項目1行(英語10語以内)。スライドは「見せるもの」、話す内容はノートへ。
- 図解が主役。文章は図の説明ではなく、図が示す主張を言い切るために使う。
- 説明の深さは不均一にする。論文の貢献の核(agent間の対話・MLLM-guided ensembleなど)は複数枚で深く、前処理や実装詳細は1行/backupへ。
- 章の頭にContents、Methodでは全体図(anchor)に繰り返し戻る(signposting)。段階的表示(アニメーション)は複雑なパイプラインを組み立てる場合だけ。箇条書きの逐次表示には使わない。
- 論文の主張と、紹介者(本人)の意見・疑問は**色とラベルで分けて**書く(例: 「Paper claims」「My view」)。考察では良い点/懸念点/ゼミで議論したい問いを明示する。
- 結果スライドは「何を主張する結果か」を主メッセージにし、表は比較対象と指標を絞って最良値を強調。定性結果は成功例だけでなく失敗例も入れる(論文に有れば)。

# 3. 視覚スタイル(既存デッキから実測。①の型)
- レイアウトは必ず **`9_ユーザー設定レイアウト`**(slideLayout6)。ここに紺の帯(1A2B4A)とスライド番号(右上, 白)が入っている。タイトルスライドのみ `タイトル スライド`。表示されるページ番号は「スライド位置 − 1」(タイトルは番号なし)。
- 色: 紺 `1A2B4A`(帯・見出し), 白(帯上の文字), 強調赤 `C00000`(結論・最良値・要注意), 本文は黒。補助色は§5参照。
- 帯上タイトル: テキストボックス x=0.18 y=0.09 h=0.64, **32pt Bold 白**。
- 小見出し: **24pt Bold 紺 1A2B4A**, x=0.18。最初の見出しは y=0.87、以降は内容に応じて 2.0〜2.5, 4.6 付近。
- 本文: **22pt 通常**(黒)。強調は **22pt Bold 赤 C00000**。箇条書きは ■(Bold)→ 子は ●。左端 x=0.18、幅は最大 12.7in。
- 図中ラベル: **20pt**(処理名は Bold)。最小でも18pt。引用元: 右上(x≈4.5, y≈0.85)に **14pt**, 論文名イタリック。参考文献は下端 **12pt**。
- 結果の表は例外的に小さい文字も可だが、できるだけ14pt以上。学術論文風(上下罫線+ヘッダ下罫線のみ、縦罫線なし)、最良値=赤Bold、自提案手法の行を強調。
- 左右余白は狭い(0.18in)。図は大きく使う。
- 数式: 可能なら OMML。無理なら Cambria Math のテキスト。
- 型にない装飾は禁止(グラデーション、影、3D、独自パレット、絵文字)。

# 4. スライドの型(パターン集)

| パターン | 用途 | 参考(執筆時点の位置) | 構成 |

| Title | 論文タイトル | 1 | 既存(更新済み) |
| Contents | 章ごとに挿入 | 7, 11, 16, 31, 41 | 5項目(01-05)の丸数字+章名。**現在の章だけ濃色/太字、他は薄いグレー**。章の頭で再掲 |

| Overall (anchor) | 全体図に戻る | 17, 21, 24, 26, 37 | 全体図を大きく表示し、**今説明する箇所を赤枠**、他は淡色。各モジュール説明の直前または直後に再掲 |

# 5. 図解のルール(PowerPointネイティブ図形で作り直すのが基本)
## 5.1 方針
- 論文図は**再描画が基本**。ネイティブ図形(長方形・角丸・平行四辺形・円筒・矢印・コネクタ)で、主メッセージが伝わる構造に組み直す。
- 切り抜き(原図のまま)にするのは: CT/MRIとマスクの重ね合わせなど定性的な医用画像、改変すると誤解を招く図、または切り抜きの方が明らかに分かりやすい場合。迷ったら再描画。
- 再描画・切り抜きとも、フッタに出典を14pt(`Adapted from … Fig. N` / 無改変は `From …`)。ノード名・矢印の意味・数値は原論文と1:1対応。存在しないモジュールや因果の変更をしない。

## 5.2 レイアウト規則
1. フロー方向は**左→右(手順)か上→下(階層)のどちらか一方**に固定。混在させない。
2. 1枚のノード数は**5±1(最大7)**。超えるときはコンテナで3群に畳むか、スライドを分割。
3. 0.05in刻みの不可視グリッドに吸着。同じ行のノードは top/height を完全一致、等間隔配置。
4. ノード間隔 ≧0.45in、コンテナ内側余白 ≧0.25in、図の外周余白は0.18in以上(本デッキの余白に合わせる)。
5. **形状の語彙を全スライドで固定**: 角丸長方形=Agent / 長方形=処理・モジュール / 平行四辺形=データ(画像・mask) / 細い角丸チップ=Tool・LLM call / 円筒=model library・知識ベース / 破線角丸矩形=stage・グループのコンテナ。
6. 矢印: 交差0・折れ0が目標(折れる場合は90°で1回まで)。矢じりは「方向のあるデータの流れ」だけ。往復は2本の片矢印を0.12in離して平行に置く。無向線は所属・構造。
7. ラベルは**直付け**(凡例を作らない)。矢印ラベルは線の中点から0.12in以内。文字は水平のみ。
8. 入出力は「形+実例」で示す(例: `CT slice 512×512` +サムネ、LLM出力は等幅16pt以上のJSONを3行まで+省略記号)。長いプロンプトは全文を載せず1行+「…」。
9. z-order: コンテナ → コネクタ → ノード → ラベル → 強調オーバーレイ。

## 5.3 色・線・文字
- 基本は **紺 `1A2B4A` + 薄い紺のtint(`E8ECF3`/`D6DEEA`) + 強調赤 `C00000`** と無彩色。赤は面積の10%未満(強調は小さく)。
- 4色以上が必要なら Okabe–Ito(`0072B2`, `E69F00`, `009E73`, `CC79A7`)から取る。コンテナの破線は灰/青 `0072B2`/緑 `009E73` を可。**赤と緑の対比だけで意味を区別しない**。
- 色だけに意味を載せない。強調は「太枠 + 濃い塗り + ラベル」の重ね掛け。モノクロ化しても区別できること。
- 線幅: 強調矢印3pt / 通常コネクタ2.25pt / コンテナ破線1.5pt / 非注目要素1pt・`BFBFBF`。注目外の要素は淡色(`BFBFBF`, 薄い塗り)にして強調と階層をつける。
- 図形内パディング0.10〜0.14in、テキストは2行以内、word_wrap有効・auto_sizeなし。

## 5.4 段階説明
- 「全体図 → 1モジュールに拡大」: 全体図(anchor)を縮小して上部/隅に置き、**今の箇所だけ赤枠、他は淡色**。拡大パネルとは細い連結線で結ぶ(虫眼鏡)。
- 複雑なパイプラインのみ、同じ図を段階的に組み立てる(ステップごとに別スライドを推奨)。

# 6. 発表ノート(speaker notes)の型
- 日本語。口語の話す内容を短い行で並べる。図の説明は「(図の説明)」と見出しを付ける。
- 想定質問は `Q.` / `A.` の対。論文に書かれていない推測は**推測だと明記**する。
- 補足知識は `Tips` 見出しの下に書く。数式の導出・データセット詳細・引用元など、スライドに載せないものはここに書く。
- 話す内容がスライドの文字の音読にならないようにする。前のスライドとのつながりを1文で入れる。

# 7. 作業手順
1. 依頼内容(章)を確認 → Notionの該当箇所を fetch → 論文PDFから `pdftotext -layout` で必要箇所を抽出し事実確認 → `presentation.xml` のセクション構成(§0)から現在のスライド位置を確認し、§4の参考番号とズレていないか照合する。
2. **章の設計メモ**: scratchpadに `design_<章>.md` が既にあれば読み込み、無ければ新規作成する。章内の全スライドについて「パターン / 主メッセージ(1文) / 図の構成(使うテンプレ・ノード数) / ノート骨子 / 状態(未着手・完了)」を先に決めて書き出す。主メッセージが書けないスライドは分割する。この設計メモは同じ作業セッション内なら次回の依頼でも読み直して続きから使う(セッションが変わっていたらNotion/論文から再構成する)。
3. 設計メモの**未着手の先頭1スライドだけ**を今回の対象として選ぶ(章全体を一度に作らない)。
4. 対象スライドの構造変更(複製・配置。セクション台帳の更新を含む。§1-10)を実施。
5. 中身を作成。python-pptx か XML 直編集。python-pptx は `text_frame.text=` で書式が消えるため `run.text` に代入するか、複製元の run の書式を保って差し替える。
6. **描画確認**: `soffice.py --headless --convert-to pdf` → `pdftoppm -r 80 -png` で対象スライドを画像化して**必ず目視確認**。LibreOffice には Meiryo UI/Segoe UI が無く代替フォントで描画されるため、文字幅は**15%程度の余裕**を見て判断する。直して再描画する修正ループは最大3回。
7. **自動QA**(scratchpadに `qa_check.py` を作って実行。違反は「即NG」ではなく警告として扱い、目視と合わせて判断): ①図形同士の重なり(コンテナ関係を除く) ②テキスト溢れの推定 ③同じ行/列の整列ずれ ④最小間隔0.45in・外周余白 ⑤フォントサイズ(図中18pt未満)とフォント名(latin/ea)違反 ⑥使用色数(無彩色除く)と赤の面積 ⑦コネクタの交差 ⑧ラベルと矢印の距離 ⑨意味ノード数7超 ⑩論文図に出典フッタが無い ⑪孤立ノード。
8. 検証: `validate.py <出力pptx> --original <バックアップ>`、`slide_text.py` で文言・ノートを再確認。
9. 設計メモの対象スライドを「完了」に更新して保存する。
10. **完了報告**(親に返す。ここで止まる): ①今回作ったスライド1枚の位置と表示ページ番号、②パターンと主メッセージ(1行)、③論文に根拠が薄い/推測を含む箇所、④QAの警告と未解決点、⑤本人に確認したい点、⑥プレビュー画像のパス、⑦章内の残り未着手スライド数。簡潔に。本人の確認が取れるまで次のスライドには進まない。
